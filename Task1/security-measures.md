# Инструменты, способы и меры обеспечения конфиденциальности

## 1. Меры по потокам данных

### 1.1. Регистрация пациента

| Этап потока | As-Is | To-Be мера |
|-------------|-------|------------|
| Сбор данных на ресепшене | Бумажная анкета, все поля | Data Minimization: только необходимые поля |
| Ввод в Excel | Ручной, без валидации | CRM-портал с валидацией и тегами `pii` |
| Создание папки пациента | `Pacient-FIO-BD` | `patient-{UUID}`, теги в метаданных |
| Хранение сканов | Общий диск | Шифрованное хранилище (SMB + BitLocker / S3 + SSE) |
| Согласие на обработку | Бумага | Электронное согласие, тег `legal.consent` |

### 1.2. Запись на приём

| Этап | As-Is | To-Be |
|------|-------|-------|
| Запись в журнал Excel | ФИО в открытом виде | ID пациента + ABAC |
| Уведомление | Телефонный звонок | SMS/e-mail через шлюз с TLS, маскирование в логах |
| Доступ врача | Общий диск | ABAC: врач → только свой журнал |

### 1.3. Ведение медицинской карты

| Этап | As-Is | To-Be |
|------|-------|-------|
| Создание записи | PDF/JPG на диске | Структурированное хранилище, тег `pii.sensitive` |
| Просмотр | Любой с доступом к диску | RBAC + ABAC, MFA |
| Передача данных | Копирование файлов | API с mTLS, Data Lineage |

### 1.4. Приём оплаты

| Этап | As-Is | To-Be |
|------|-------|-------|
| Оплата у кассира | Наличные/карта | Платёжный шлюз (PCI DSS) |
| Дублирование в Excel | Да | **Устранить** — единый источник в 1С/CRM |
| ККМ → 1С | OLE/TCP | Защищённый адаптер, минимизация полей |

### 1.5. Бухгалтерский учёт

| Этап | As-Is | To-Be |
|------|-------|-------|
| 1С файловый режим | Общий сервер | Клиент-серверный режим, сегментация сети |
| Кадровые данные | В той же 1С | Отдельный контур HR, тег `hr` |
| Отчёты для ФНС | Экспорт файлов | Шифрованный экспорт, аудит |

### 1.6. Лабораторные анализы

| Этап | As-Is | To-Be |
|------|-------|-------|
| Реестр Excel | Общий диск | API лаборатории, тег `pii.sensitive` |
| Привязка к пациенту | Вручную | Автоматическая по ID, BOLA-защита |
| Хранение результатов | Файлы | Шифрованное хранилище, retention policy |

### 1.7. Учёт ТМЦ

| Этап | As-Is | To-Be |
|------|-------|-------|
| 1С Торговля | Файловый режим | Сегментация; ПДн пациентов не хранить |
| Интеграция с бухгалтерией | OLE | Защищённая интеграция, Data Lineage |

## 2. Каталог инструментов

### Хранение и шифрование

| Инструмент | Назначение |
|------------|------------|
| PostgreSQL + pgcrypto / TDE | Структурированные ПДн и мед. данные |
| MinIO / S3-compatible + SSE-KMS | Файлы, сканы, заключения |
| HashiCorp Vault | Управление ключами шифрования |
| BitLocker / LUKS | Шифрование дисков сервера (переходный период) |

### Доступ и идентификация

| Инструмент | Назначение |
|------------|------------|
| Active Directory + группы | Базовый IAM (существует) |
| Keycloak / AD FS | SSO, OIDC для порталов |
| OPA | ABAC policy engine по тегам |
| MFA (TOTP/Hardware key) | Привилегированный доступ к `pii.sensitive` |

### Каталог, lineage, тегирование

| Инструмент | Назначение |
|------------|------------|
| OpenMetadata | Каталог, теги, lineage |
| Microsoft Purview | Классификация файлов на Windows Server |
| Apache Atlas | Альтернатива для data lake |

### Мониторинг и аудит

| Инструмент | Назначение |
|------------|------------|
| Elastic Stack | Аудит доступа, поиск аномалий |
| Victoria Metrics | Метрики безопасности |
| Watcher / Alertmanager | Алерты при несанкционированном доступе |
| OSSEC / Wazuh | FIM — контроль изменений файлов |

### Разработка и CI/CD

| Инструмент | Назначение |
|------------|------------|
| Semgrep | Статический анализ: запрет логирования PII |
| OPA Conftest | Проверка манифестов K8s на политики |
| GitLab CI | Gate: релиз не проходит без проверки тегов |

### Аналитика (BI/ML)

| Инструмент | Назначение |
|------------|------------|
| ClickHouse (обезличенные данные) | Аналитика без PII |
| Jupyter + anonymization pipeline | ML на псевдонимизированных данных |
| Airflow | ETL с применением тегов и lineage |

## 3. Архитектурные практики

| Практика | Реализация |
|----------|------------|
| **Privacy by Design** | Теги и политики на этапе проектирования API и схем БД |
| **Data Minimization** | API-контракты отдают только необходимые поля |
| **Data Lineage** | OpenMetadata: источник → ETL → BI/ML |
| **Zero Trust** | Проверка на каждом запросе (OPA), не только периметр |
| **Defense in Depth** | Сегментация сети + шифрование + аудит + DLP |
| **Secure by Default** | Новые интеграции наследуют теги и политики из каталога |

## 4. Соответствие 152-ФЗ (ключевые меры)

| Требование | Мера |
|------------|------|
| Правовые основания обработки | Тег `legal.*`, реестр согласий в CRM |
| Меры защиты ПДн | Шифрование, RBAC/ABAC, аудит |
| Специальные категории (ст. 10) | Отдельный домен `domain.medical`, усиленная защита |
| Права субъекта (доступ, удаление) | API ЛК + workflow удаления по тегу `policy.delete.on_request` |
| Уведомление Роскомнадзора | Реестр обработок в OpenMetadata |
| Локализация данных | Хранение на серверах в РФ (on-prem / российское облако) |
